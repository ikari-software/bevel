# Bevel Code Map

For shared format rules, see `docs/code-maps/FORMAT.md`. Inventory: `docs/code-maps/INVENTORY.md`.

## Snapshot
- Themable desktop-shell replacement (Windows 2000/XP reimagined "as if designed in 2026"), macOS-first.
- .NET 10 + Avalonia — ~16 projects under `src/` — plus a Swift helper (`native/helper-macos`) over gRPC/UDS.
- Multi-process **only** (no single-process mode, bevel-dwhy): an argument-less launch is `--role=launcher`, which supervises a headless `--role=core` + `--role=taskbar` (+ `--role=desktop` only when toggled on, off by default). Each Explorer window is its own `--role=explorer` process (`Program.SpawnExplorer`).

## Start Here
- `src/Bevel.App/Program.cs` — process entry; `--role` / `--pal` parsing dispatches to the right surface.
- `src/Bevel.App/CompositionRoot.cs` — the single place services are wired (DI). Change wiring here, not per-project.
- `src/Bevel.App/Supervision/RoleProcessSupervisor.cs` — spawns/restarts child roles; holds a **mutable** child set (`SpawnRoleAsync`/`CloseRoleAsync`/`IsRoleRunningAsync`) so the desktop can be added/removed at runtime (a user-hidden desktop is NOT auto-respawned). Heartbeats (`RoleHeartbeatStore` under `BevelRuntimeDir.HealthDir`) + `ShellHealthMonitor` make startup fail / version skew / lost IPC visible and held instead of a silent crash-loop (bevel-9h7n). `Program.RunLauncher` + `Supervision/LauncherControl.cs` own the verbs.
- `src/Bevel.UI/` — shared chrome (`BevelWindow`) + theming. Live theme colour lives here, **not in XAML** (see Notes).
- `src/Bevel.Taskbar/Model/ShellModel.cs` — background model owning the window/app/tray observable collections.
- `src/Bevel.Taskbar/Model/TaskButtonClickPolicy.cs` — what a task-button click *means* (today: does re-clicking the active window minimize it — bevel-au94, `docs/design/taskbar-reclick-minimize.md`). One shared mutable holder because `ShellModel` builds buttons with no settings of its own; `TaskbarView` writes the mode on every settings apply, `TaskItemViewModel.ToggleAsync` reads it at click time. Modifier chords are read from the platform's LIVE modifier state, never from an input event — the bar is non-activating.
- `native/helper-macos/Sources/BevelHelper/` — window/tray enumeration; a separate TCC identity (see Coupling).

## Entrypoints
- Roles: `--role=launcher|core|taskbar|explorer|desktop` (+ `--open-path=`/`--select=`). **No `all` role** — default is Launcher (`RoleSelection.cs`). PAL: `--pal=fake|macos|windows` (aliases `mac`/`osx`, `win`). Default PAL is the host OS on macOS/Windows, Fake elsewhere (`PalSelection.cs`). Parsed in `Program.cs` + `RoleSelection.cs` + `PalSelection.cs`.
- `bevelctl` binary + `bevel://` URL verbs → automation socket (fixed path `~/.config/bevel/bevelctl.sock`, `Bevel.Interop/Cli/AutomationSocket.cs`) + inbound Apple Events. **Hosted by the persistent TASKBAR** now (`AutomationSocketHost`, wired only for the Taskbar role in `CompositionRoot`), NOT the on-demand Explorer (bevel-e7a7).
- Packaging: macOS `packaging/macos/{build-app,sign-app,notarize-app,make-dmg}.sh` (+ `dev-sign.sh` for fast local signing). `build-app.sh` is clean-by-default (`CLEAN=0` for incremental) and gates the single-file bundle through `verify-bundle.py` — every UI assembly must carry compiled XAML + `!AvaloniaResources`, or the build fails instead of shipping a `XamlLoadException` (bevel-9pgv). Install to `/Applications` via `install-local.sh` (canonical notarized bundle). Windows: `packaging/windows/publish.sh` (self-contained `win-x64` → `dist/win-x64/Bevel.App.exe`) then `deploy-ssh.sh` / `deploy-to-nucbox.sh` onto the LAN box. Runtime dir on Windows is `%LOCALAPPDATA%\bevel` (`BevelRuntimeDir`); macOS/Linux stay under `$TMPDIR`. No Swift helper on Windows — Core hosts an in-process WinEvent pump + shared STA COM worker.

## Contracts And Data
- gRPC contracts are **source-of-truth in `proto/`** — verify message shapes there, don't infer from a call site. Transports: `Bevel.Ipc` + `Bevel.ShellCore.Ipc` (UDS, per-session HMAC nonce auth, socket dir 0700).
- Settings (**core-owns-settings**, bevel-6nve): `Bevel.Core/SettingsService.cs` — one JSON blob row in SQLite at `~/.config/bevel/settings.db`. The `--role=core` process is the **SOLE opener + writer** of the DB (the Fake PAL — the dev/test shell — also binds the real service since it's single-process). Peer roles (Taskbar/Explorer/Desktop) get `Bevel.App/ShellCore/RemoteSettingsService.cs` instead: reads are a cache of the core's snapshot, writes send a **changed-keys merge patch** to the core over a shell-core client, and the core **broadcasts** a fresh snapshot back (`SettingsSnapshot` on connect, `SettingsChanged` after each apply) — no peer ever opens the DB. `ISettingsService` is registered **role-aware in `CompositionRoot`** (real for Core + Fake PAL; Remote for peers; Explorer/Desktop carry a settings-only client while their window/app/tray stay direct-PAL). The old **750 ms poll and the cross-process CAS-merge are retired** (beads y7r4/ha3x dissolved) — a single writer needs neither. **`settings.json` is a passive export — editing it does nothing; change settings via `ISettingsService`.** Sharp edges (all three are exactly where a future edit breaks): (1) the **taskbar's settings peer uses its OWN keyed `"settings"` `ShellCoreClient`, NOT the shared window/tray client** — RemoteSettingsService connects during startup `LoadAsync`, and sharing the tray client would let that early connect eat the core's on-connect `TraySnapshot` before the tray adapter subscribes (the tray has no reconcile backstop). (2) `ShellCoreClient` **retries a FAILED FIRST connect** (arms its reconnect supervisor) so a settings peer racing core boot doesn't strand on defaults. (3) `ShellCoreServer.StartAsync` **starts serving BEFORE** the helper-dependent window/tray seed, so peers get settings without waiting on the helper.
- Domain / VFS / services: `Bevel.Core` — **must not reference Avalonia** (ARCH-02).
- PAL: interfaces in `Bevel.Pal.Abstractions`; `Bevel.Pal.MacOS` (AX + Swift helper), `Bevel.Pal.Windows` (Win32/COM in-proc; Core owns EnumWindows + WinEvent + STA file/icon COM), `Bevel.Pal.Fake` (deterministic; what most tests + `--pal=fake` use). Taskbar on both real PALs is a shell-core *client* for windows/apps/tray; Explorer/Desktop keep direct PAL for those and a settings-only client.

## Coupling
- **The `--role=core` process is the SOLE owner of the Swift helper** (core-owns-helper, bevel-6nve): `HelperLifecycle` is added as a hosted service ONLY for Core in `CompositionRoot` (Explorer/Desktop keep the singleton lazy, never started); the core serves window/tray/app state to peers over the shell-core IPC, so a peer NEVER launches the helper. `Bevel.Pal.MacOS/HelperProcessHost.cs` launches it; `ResolveHelperBinary` locates the binary (bundle or dev-build). The helper (`pl.ikari.bevel.helper`) is a **separate TCC entity** needing its OWN Accessibility + Screen Recording grants; it prompts on launch; its diagnostics go to **stderr only**.
- Icons render off-thread, cached, shared across processes via a memory-mapped BGRA pool (`MmfBgraPool`) — not re-rendered per process.

## Local Commands
- Build `dotnet build Bevel.sln -clp:ErrorsOnly` · Test `dotnet test Bevel.sln`.
- Safe dev run: `dotnet run --project src/Bevel.App -- --pal=fake` (Fake PAL, no helper/TCC prompts).
- Dev `.app`: `./packaging/macos/build-app.sh && ./packaging/macos/dev-sign.sh`.
- Benchmarks: `benchmarks/Bevel.Benchmarks` — **not** in `Bevel.sln`; build/run explicitly.

## Notes
- **Live theme colour = two runtime engines, not XAML.** `LunaVariantService` (`src/Bevel.UI/Luna/LunaVariant.cs`; Luna colours Blue/Silver/Black/Purple × gloss) and `ColorSchemeService` (`src/Bevel.UI/ColorSchemeService.cs`; Win2000 schemes) OVERRIDE static tokens and must be `Clear()`'d symmetrically when switching away. Editing the static `.axaml` alone won't change the running look.
- **Never block the Avalonia UI thread** — no `.Result`/`.Wait()`; do heavy work off-thread, marshal the cheap result back.
- App pins `RequestedThemeVariant="Light"`; don't add variant/scope overrides (a Dark leak washes out popups).
- A Popup only opens if its host is attached to a visual tree with a TopLevel — a VM-only `IsOpen=true` can pass a unit test while nothing ever shows (`avalonia-popup-needs-visual-tree`).
- **Task-button Tabs submenu = Apple Events + AX** (bevel-a40b/bevel-osad/bevel-l17f). `ITabProvider` (`Bevel.Pal.Abstractions`) → `Bevel.Pal.MacOS/MacOSTabProvider.cs`, an `/usr/bin/osascript` child per query (RS/US-framed rows; iTerm2 / Chromium-family / Safari dialects; failures collapse to empty by contract). The Gecko family (Zen/Firefox) has NO AppleScript tab dictionary — `GeckoTabEngine.cs` serves it in-proc via accessibility (`AXTabButton` walk + `AXPress`; systemwide AX messaging timeout; press-safety policy in `SelectTarget` refuses ambiguous stale rows), and `GeckoSessionStore.cs` (mozLz4 session store) backfills tab urls by title. Favicons: `TabFaviconStore.cs` reads the browsers' own on-disk caches (Chromium `Favicons` / Gecko `favicons.sqlite`) — sharp edge: the live DBs are UNREACHABLE through both SQLite (Firefox holds locking_mode=EXCLUSIVE) and managed file APIs (.NET's macOS flock contends with SQLite's fcntl locks), so the store raw-syscall-copies then queries. Registered direct in every role like `IFileOpener`. `TaskbarView.PrefetchTabsAsync` fetches + decodes icons off-thread BEFORE `TaskButtonMenu.TryShow` (an open MenuFlyout never repaints) under a 1.5 s budget; the submenu height-caps at 480px and scrolls via the Classic template's own menu scroll viewer. Sharp edge: keep the batched `every tab of window wi` property reads — per-tab reads cost ~24 ms each and measured 8.9 s on a 182-tab sidebar (a pinning test guards this).
- **Task-button unread badge = the DOCK's a11y tree, not the app** (bevel-ijln). `IAppBadgeSource` (`Bevel.Pal.Abstractions/AppBadges.cs`) → `Bevel.Pal.MacOS/MacOSAppBadgeSource.cs`; `Bevel.Pal.Fake/FakeAppBadgeSource.cs` injects labels for tests/`--pal=fake`; Windows registers `NullAppBadgeSource`. **`NSDockTile.badgeLabel` is NOT readable cross-app** — it belongs to the owning process's own `NSApp.dockTile`, and AppKit exposes no foreign tile; don't go looking for one. The only public path is the Dock process (`com.apple.dock`) accessibility tree: per-app `AXApplicationDockItem` → `AXStatusLabel` (the badge), `AXURL` (→ bundle id via `CFBundle`), `AXTitle` (display name). Consequences to keep in mind before "fixing" a missing count: it needs the **Accessibility grant** (no grant → empty, never a throw); an app the Dock doesn't list (`LSUIElement`, Dock-hidden) publishes **nothing**; the label is the Dock's own string, so wide counts arrive **ellipsized** (`"..82"`) — hence `BadgeText` is a string shown verbatim and `BadgeCount`/`AppBadge.Count` is null unless it parses; and it's a **2 s poll** (no public change notification), riding `ShellModel.ReconcileLoopAsync` off-thread with only the finished key→label index Posted to the UI thread. Matching lives in `Bevel.Taskbar/Model/TaskBadges.cs` (bundle id first, app display name as the case-insensitive fallback). **Counts are never inferred from window titles** — a Slack-style `"(7) general"` title must stay badge-free (pinned by `tests/Bevel.Taskbar.Tests/TaskBadgeTests.cs`). The pill is `src/Bevel.Taskbar/TaskBadge.axaml` (`Bevel.Theme.TaskBadge`, a code-drawn rounded `ContentControl`), placed **inline between icon and title** in both task-button templates — not overlaid on the icon, so it survives an icon-size change — and painted from `Bevel.Brush.Highlight`/`HighlightText` (**never a hardcoded macOS red**), which both recolor engines already own. Sharp edge: `Bevel.Brush.HighlightText` was missing from `LunaTokens.axaml` and was added there for this — a token-driven colour must exist in **every** skin or it renders invisible. Distinct from the grouped button's `"(N)"` glomming count (R-TB-6).
- **Stack flyout = preview grid, and previews are a PAL capability of their own** (bevel-12g/bevel-9elh). `IThumbnailProvider` (`Bevel.Pal.Abstractions`) is CONTENT previews — what is in the file — as opposed to `IIconProvider`'s file-TYPE icons; it returns null whenever the backend can't decode that format, and callers fall back to a larger type icon rather than pretending. `Bevel.Pal.MacOS/MacOSThumbnailProvider.cs` decodes images through ImageIO (`CGImageSourceCreateThumbnailAtIndex`) and PDFs through `CGPDFDocument` — pure C frameworks, all P/Invoke, safe off the main thread; anything else (text, Office, video) has NO preview yet and would need a Quick Look generator. Registered direct in every role like `IFileOpener`, deliberately NOT through the shared icon pool (a thumbnail is per-file content, not a reusable type icon). UI: `src/Bevel.Taskbar/StackFlyoutView.axaml` (its own file — `TaskbarView.axaml` only hosts it in the stack `Flyout`) over `Model/PreviewLoader.cs`, which caches cell bitmaps per path, shares them across cells and `Trim`s them to the folder's live entries. Sharp edge for render tests: the first `CaptureRenderedFrame()` after a batch of bitmaps lands can still be the pre-bitmap composite — capture twice (`RenderStackGridTest.Capture`).
- **Window-chrome geometry is token-driven**, not hand-tuned in the template: the Win2000 border bands (2px bevel · 2px sizing-frame face · 18px caption · 1px separator) come from `theme.json` metrics (`CaptionMargin`, `WindowContentInset`, `CornerRadius`) → `Tokens.axaml` / `LunaTokens.axaml` via `tools/ThemeGen`, and are **pixel-guarded** by `tests/Bevel.Taskbar.Tests/RenderWin2000BorderTest`. Vendored window template: `third_party/classic-avalonia/.../Styles/Window.axaml`; caption buttons: `.../Styles/CaptionButtons.axaml`.
- **Explorer left pane is resizable + persistent.** `LeftSplitter` drag (code-behind pointer-capture in `FileManagerWindow.axaml.cs`, `OnSplitter*`) resizes column 0; the width (`ExplorerLeftPaneWidth`) and the Folders-vs-info toggle (`ExplorerFoldersOpen`) persist via `SettingsService` and restore in `SetSettingsService`. `Components/InfoPane` owns four independently selectable era presets (Win2000/Me Web View, XP Common Tasks, Vista/7 navigation, Win95/NT4 minimal); `FileManagerWindow.UpdateInfoPane` supplies their shared live places, commands, and selection details. Luna's pane aliases preset-local fallback brushes to `Luna.Brush.InfoPane*`; `LunaVariantService.TransformInfoPane` derives each semantic role from the configured source color plus the active base hue and role-specific S/L treatment. Sharp edge: `ApplyFolderOptions` re-lists the directory **only** when a listing-affecting input (hidden files / extension hiding) changed — layout-only settings writes (pane width, toggle, info-pane style) fan out through `App`'s `settings.Changed` but must NOT reset sibling windows' items/scroll/selection. **Don't re-add an unconditional `ReloadWithCurrentOptions()` there.**
- **Type-ahead is a shared service.** `src/Bevel.Core/Input/TypeToFind.cs` (pure, clock-injected, generic) is the one correct type-ahead matcher — prefix accumulation, single-char cycling, forward wrap, `OrdinalIgnoreCase` — fed from real `TextInput` so digits + accents work. `ItemView` uses it (`OnTextInput` → `MoveTo`). The folder tree / Start menu / folder picker / taskbar / desktop grid should **reuse it**, not re-derive a `Key`-decoding copy (that path had a dead digit map, backwards wrap, and no cycling — bevel-p3v3).
- **Accessibility has two non-obvious seams.** (1) The Explorer file list exposes screen-reader semantics through `Components/ItemViewAutomation.cs`: each row's visual root is wrapped in a layout-transparent `ItemRow : Decorator` carrying an `ItemRowAutomationPeer` (ListItem + `ISelectionItemProvider` mirroring `ItemViewModel.IsSelected`), and the container is `ItemList : ItemsControl` (List role; `StyleKeyOverride => typeof(ItemsControl)` so it still finds the ControlTheme and realizes rows). Sharp edge: **don't rewrite the `ItemsControl` to a `ListBox`** for a11y — it would break the marquee, rect-based `Hit()`, and the `VirtualizingWrapPanel`; the Decorator+peer is deliberately inert to layout (`Hit()`/`Marquee()` measure the `ContentPresenter`). (2) The taskbar uses **menu-scoped key focus** (bevel-vk4n): it is non-key at idle and `TaskbarWindow.SetKeyFocusAllowed(bool)` flips `canBecomeKeyWindow` true **only** while an owned menu/popover is open (depth-counted `EnterMenuScope`/`ExitMenuScope` in `TaskbarView`), capturing + re-activating the prior app so focus returns. **Never restore the unconditional `SetCanBecomeKeyWindow(false)`-only path or set it `true` at idle** — the bar must not steal focus. From-idle `Ctrl/Option+Esc` rides a native global keyDown monitor that needs the Input Monitoring TCC grant (`taskbar-idle-hotkey-needs-input-monitoring`).
- **Automation window seam is role-aware** (`IShellSurface`, bevel-e7a7). Explorer keeps the in-process `FileManagerShellSurface` (addresses live windows by registry id). Every OTHER role — crucially the taskbar host — binds `SpawningShellSurface`: `open`/`reveal` **spawn** a `--role=explorer` (via `--open-path=`/`--select=`) instead of building a malformed surface-less window in-process. Registered in `CompositionRoot.AddBevelModules`.
- **Taskbar↔Explorer control channel** (bevel-uldj) is how `select`/`query windows`/`query selection` reach live windows in split mode. Each Explorer hosts an `ExplorerControlServer` on a per-pid rendezvous socket (`Bevel.App/ShellCore/ExplorerControlEndpoint.cs`, `explorer-<pid>.sock` in a 0700 env-published dir); the taskbar dials them via `TaskbarExplorerControlClient` to aggregate queries (frontmost-first) and route `select`. Composite `WindowRef = (regId<<16)|localId` (regId starts at 1 so a composite is never 0); `Decode` routes a ref back to its owning pid. `SpawningShellSurface`'s channel client is optional — Desktop/Core bind the surface but leave it null and fall back to the clear "no window" result.
- **Start-menu Show/Hide Desktop toggle** (bevel-gdie): the desktop surface is OFF by default. Start-menu verbs go child→launcher over `LauncherControl` (`SpawnDesktop`/`CloseDesktop`/`QueryDesktop`), driving the supervisor's runtime add/remove. Set `BEVEL_ENABLE_DESKTOP=1` to spawn it at boot instead.
- **Process health is heartbeat-driven, not just `HasExited`.** Children write `starting`/`ready`/`failed` + `BuildStamp` under `BevelRuntimeDir.HealthDir`; the launcher's `ShellHealthMonitor` Holds a XAML/startup failure (native alert + `status` file) instead of crash-looping, Restarts a stamp/protocol mismatch onto the current binary, and Restarts the core when a ready UI has no link. Not-this: `LostCoreAutoRepair` is the *taskbar-side* complement (click-equivalent RestartCore after a grace period) — it does not replace the launcher monitor.
- **Build/launch hygiene.** Packaged publish is `PublishReadyToRun` (crossgen per role, bevel-k93j). A normal `dotnet build` emits **no `Bevel.App` apphost** — `UseAppHost` is gated on `BevelPackaging` in `Directory.Build.targets` (a stray apphost pollutes Spotlight/LaunchServices; the packaged bundle also drops a `.metadata_never_index` marker). So `dotnet run` executes the DLL via the shared `dotnet` host; only `/Applications/Bevel.app` (via `install-local.sh`) is a real app.
