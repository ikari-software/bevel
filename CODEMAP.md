# Bevel Code Map

For shared format rules, see `docs/code-maps/FORMAT.md`. Inventory: `docs/code-maps/INVENTORY.md`.

## Snapshot
- Themable desktop-shell replacement (Windows 2000/XP reimagined "as if designed in 2026"), macOS-first.
- .NET 10 + Avalonia — ~16 projects under `src/` — plus a Swift helper (`native/helper-macos`) over gRPC/UDS.
- Multi-process **only** (no single-process mode, bevel-dwhy): an argument-less launch is `--role=launcher`, which supervises a headless `--role=core` + `--role=taskbar` (+ `--role=desktop` only when toggled on, off by default). Each Filer window is its own **supervised** `--role=filer` launcher child (`FilerSupervisor`), opened via the `SpawnFiler` launcher verb; plus ONE hidden pre-warmed `--role=filer --park` child so an open is a `Show` dial, not a process cold start (bevel-t48y). `Program.SpawnFiler` remains only as the unsupervised dev fallback.

## Start Here
- `src/Bevel.App/Program.cs` — process entry; `--role` / `--pal` parsing dispatches to the right surface.
- `src/Bevel.App/CompositionRoot.cs` — the single place services are wired (DI). Change wiring here, not per-project.
- `src/Bevel.App/Supervision/RoleProcessSupervisor.cs` — spawns/restarts child roles; holds a **mutable** child set (`SpawnRoleAsync`/`CloseRoleAsync`/`IsRoleRunningAsync`) so the desktop can be added/removed at runtime (a user-hidden desktop is NOT auto-respawned). Heartbeats (`RoleHeartbeatStore` under `BevelRuntimeDir.HealthDir`) + `ShellHealthMonitor` make startup fail / version skew / lost IPC visible and held instead of a silent crash-loop (bevel-9h7n). `Program.RunLauncher` + `Supervision/LauncherControl.cs` own the verbs.
- `src/Bevel.App/Supervision/FilerSupervisor.cs` — the filer **sibling** supervisor (bevel-t48y): instance-keyed (N windows, one process per open), spawned as DIRECT launcher children via the generalized `CreateRoleStartInfo` (never `/bin/sh`+nohup — TCC attribution). Close-vs-crash is judged by **exit code**: 0 = the user closed the window → de-supervise, NEVER respawn (bevel-gdie); anything else = crash → respawn at last-open-path with poll-tick backoff. The parked pre-warm: ONE hidden `--park` child at boot (keep-1); an open CLAIMS a parked instance under the gate before the bounded `Show` dial (`TaskbarFilerControlClient.ShowByPidAsync` on the claimed park's `filer-<pid>.sock`), a successful handoff spawns the replacement park, a failed dial reverts the claim and cold-spawns. Every filer's stderr is pumped to `bevel-filer-<pid>.log` next to the restart diag log (a dying peer's managed stack exists ONLY in its stderr). **Filers write NO heartbeats** (supervisor-only liveness): N instances would clobber the single `ShellRole.Filer` slot, so `ShellHealthMonitor` is deliberately unwired for filers and filer churn can never Hold.
- `src/Bevel.UI/` — shared chrome (`BevelWindow`) + theming. Live theme colour lives here, **not in XAML** (see Notes).
- `src/Bevel.UI/BevelMark.cs` — Bevel's own logo (glass cube, spectrum edges), code-drawn in a 100-unit box; ONE mark, two optical sizes (`LayersFor`: core + depth rays from 24px, plain glass below; `fullDetail` forces the core — the Appearance "Detailed Start badge" option, `BevelSettings.StartBadgeFullDetail`). Sharp edge: `DrawOrder` is what makes the core read as INSIDE the glass (near faces are translucent and painted OVER it) — pinned by `BevelMarkTests`, don't reorder. Faces are fixed translucent tints on purpose (they show the button colour through; no tokens for the recolour engines to override); the 9 spectrum edges are brand-fixed. Not-this: never put a vendor logo or a 2x2 blue/green/red/yellow grid here — that is the highest-risk IP item (`bevel-legal-branding`). `src/Bevel.Taskbar/StartLogo.cs` only picks Bevel mark vs Tux (Linux); badge size is the theme token `Bevel.Metric.StartBadgeSize` (20 in both themes), applied live by `TaskbarView.RebuildStartBadge`.
- `src/Bevel.Taskbar/Model/ShellModel.cs` — background model owning the window/app/tray observable collections.
- `src/Bevel.Taskbar/Model/TaskButtonClickPolicy.cs` — what a task-button click *means* (today: does re-clicking the active window minimize it — bevel-au94, `docs/design/taskbar-reclick-minimize.md`). One shared mutable holder because `ShellModel` builds buttons with no settings of its own; `TaskbarView` writes the mode on every settings apply, `TaskItemViewModel.ToggleAsync` reads it at click time. Modifier chords are read from the platform's LIVE modifier state, never from an input event — the bar is non-activating.
- `native/helper-macos/Sources/BevelHelper/` — window/tray enumeration; a separate TCC identity (see Coupling). Boot must **never** TCC-prompt (bevel-llfm): only `AXIsProcessTrusted` / `CGPreflightScreenCaptureAccess`; interactive grants via `MacOSPermissionBroker.RequestAsync`. `WindowServiceImpl` reads top-down as: `beginPass` (ONE CG query + AX correlation + `SpaceContext` + true z-order, shared by every window) → `describe` (Dock app? → descriptor → AX state → ordered `dropReason` gates) → `markFocusedWindow`. The policy lives in small pure units, each unit-tested in `WindowPolicyTests`: `OffscreenWindowTracker` (off-screen + AX-less: tombstone vs live), `FocusResolver`/`FocusEvidence` (pressed state), `ActivationPlan`/`WindowActivator` (what a taskbar click does), `SkyLight` (dlsym'd private WindowServer calls; every symbol optional). Facts grep won't show: (1) an off-screen AX-less window on a Space **no display is showing** is definitively live (`SpaceContext.isOnOtherSpace`, via `CGSCopySpacesForWindows` vs each display's Current Space) — a closed window's tombstone keeps its old Space and lingers 10 s+, so Spaces membership alone can't identify tombstones; (2) **only the `.optionOnScreenOnly` CG list is z-ordered** — `.optionAll` order is not depth (deriving "topmost" from it pinned one window forever); (3) `SkyLight.focusWindow` (`_SLPSSetFrontProcessWithOptions` + `SLPSPostEventRecordTo`) makes a window *key* but does **not** switch Spaces — Space switch is `SkyLight.switchToSpace` (**warp + synthetic click, leave pointer** on the owning display: Hide/Show/SetCurrent alone only flips CGS bookkeeping; Dock recomposites that display only when the pointer is on it, and a click — not mouseMoved / warp-hold-restore — is what forces the paint; restoring the cursor in the same turn leaves the UI stuck until a real click minutes later, bevel-szw4 / Jorvik notes); always follow app-level activate with `focusViaWindowServer` so a multi-Space app cannot front a sibling session; do **not** follow with `SLSSpaceSetFrontPSN` (`setFrontOnSpace`) — it re-fires `didActivateApplication` while AX still names a Jump sibling; instead `WindowServiceImpl.performActivation` suppresses `broadcastFocusForApp` for the ladder duration and emits `activate-focus-pin` for the requested `cgID` (ce-optimize exp1+exp2: sibling_steal_rate 0.538→0.0); `SLSOrderWindow` on a foreign window is refused (rc 1000) — `AXRaise` is the only raise, so AX-less apps (Kiro) get key-focus without a raise; (4) `currentSpaceIDs()` is a **per-display set** — never a single global Space; (5) the tombstone counter advances once per **reconcile** pass, never in `describe` (`beginPass(forReconcile:)`). Not-this: don't set `AXManualAccessibility` — for an app answering `-25211` every AX call fails alike, so the flip cannot work (removed).

## Entrypoints
- Roles: `--role=launcher|core|taskbar|filer|desktop` (+ `--open-path=`/`--select=`). **No `all` role** — default is Launcher (`RoleSelection.cs`). PAL: `--pal=fake|macos|windows` (aliases `mac`/`osx`, `win`). Default PAL is the host OS on macOS/Windows, Fake elsewhere (`PalSelection.cs`). Parsed in `Program.cs` + `RoleSelection.cs` + `PalSelection.cs`.
- `bevelctl` binary + `bevel://` URL verbs → automation socket (fixed path `~/.config/bevel/bevelctl.sock`, `Bevel.Interop/Cli/AutomationSocket.cs`) + inbound Apple Events. **Hosted by the persistent TASKBAR** now (`AutomationSocketHost`, wired only for the Taskbar role in `CompositionRoot`), NOT the on-demand Filer (bevel-e7a7).
- Packaging: macOS `packaging/macos/{build-app,sign-app,notarize-app,make-dmg}.sh` (+ `dev-sign.sh` for fast local signing). `build-app.sh` is clean-by-default (`CLEAN=0` for incremental) and gates the single-file bundle through `verify-bundle.py` — every UI assembly must carry compiled XAML + `!AvaloniaResources`, or the build fails instead of shipping a `XamlLoadException` (bevel-9pgv). Install to `/Applications` via `install-local.sh` (canonical notarized bundle). Windows: `packaging/windows/publish.sh` (self-contained `win-x64` → `dist/win-x64/Bevel.App.exe`) then `deploy-ssh.sh` / `deploy-to-nucbox.sh` onto the LAN box. Runtime dir on Windows is `%LOCALAPPDATA%\bevel` (`BevelRuntimeDir`); macOS/Linux stay under `$TMPDIR`. No Swift helper on Windows — Core hosts an in-process WinEvent pump + shared STA COM worker.

## Contracts And Data
- gRPC contracts are **source-of-truth in `proto/`** — verify message shapes there, don't infer from a call site. Transports: `Bevel.Ipc` + `Bevel.ShellCore.Ipc` (UDS, per-session HMAC nonce auth, socket dir 0700).
- **One shell, one owner per socket** (bevel-wio0). The launcher takes `~/.config/bevel/shell.lock` (`Supervision/ShellInstanceLock.cs`, flock; pid in `shell.lock.pid`) BEFORE anything else — a second launch prints "already running" and exits. Every fixed-path UDS server (`core.sock`, `launcher.sock`, `bevelctl.sock`, `filer-<pid>.sock`) claims its path through `Bevel.ShellCore.Ipc/UdsSocketClaim.cs`: **probe-then-bind** (a live answer → `UdsSocketBusyException`, stand down; only ECONNREFUSED/ENOENT is reclaimed) and **owner-only unlink** (close the listener, re-probe, delete only if nobody answers). Not-this: `File.Delete(path)` before `Bind` — that was the hijack. The launcher's core health probe is `Supervision/CoreSocketProbe.cs` — an authenticated `UdsMessageClient.ProbeAsync` with the session nonce (`ProbeCapability`, answered at the handshake, never registered as a client), so a socket that exists or even connects but belongs to a foreign core reads as unhealthy; a supervised core that finds the path busy `ReportFailed`s and the launcher Holds + alerts.
- Settings (**core-owns-settings**, bevel-6nve): `Bevel.Core/SettingsService.cs` — one JSON blob row in SQLite at `~/.config/bevel/settings.db`. The `--role=core` process is the **SOLE opener + writer** of the DB (the Fake PAL — the dev/test shell — also binds the real service since it's single-process). Peer roles (Taskbar/Filer/Desktop) get `Bevel.App/ShellCore/RemoteSettingsService.cs` instead: reads are a cache of the core's snapshot, writes send a **changed-keys merge patch** to the core over the process's ONE shell-core client, and the core **broadcasts** a fresh snapshot back (`SettingsSnapshot` in the Hello burst, `SettingsChanged` after each apply; the peer also re-pulls `GetSettings` on every link restore) — no peer ever opens the DB. `ISettingsService` is registered **role-aware in `CompositionRoot`** (real for Core + Fake PAL; Remote for peers). The old **750 ms poll and the cross-process CAS-merge are retired** (beads y7r4/ha3x dissolved) — a single writer needs neither. **`settings.json` is a passive export — editing it does nothing; change settings via `ISettingsService`.** Sharp edges (all exactly where a future edit breaks): (1) **ONE `ShellCoreClient` per process** (bevel-4zfs): the core pushes NOTHING on connect, so the settings peer's early `LoadAsync` connect (a plain `GetSettings` pull) can't eat anyone's snapshot — the taskbar sends **Hello** (`StartSessionAsync` in `App.CreateTaskbar`, after every adapter is subscribed), and the tray has its own `GetTrayItems` pull backstop. (2) `ShellCoreClient` **retries a FAILED FIRST connect** (arms its reconnect supervisor) so a settings peer racing core boot doesn't strand on defaults. (3) `ShellCoreServer.StartAsync` **starts serving BEFORE** the helper-dependent window/tray seed, so peers get settings without waiting on the helper. (4) **A peer's first paint never waits on the socket** (bevel-7s9n): `Bevel.Core/SettingsSnapshotCache.cs` is the peer's write-through copy of the last core snapshot at `~/.config/bevel/peer-settings-cache.json`; `RemoteSettingsService.LoadAsync` projects it with zero IPC and pulls the live one in the background. The first live snapshot is compared to the cache by CONTENT (`SettingsService.BlobsEquivalent`, not bytes — the cache is re-serialised) and raises `Changed` only on a real difference; later ones must carry a higher store version. A blob that does not parse as a JSON object is **refused, never projected as defaults** (`SettingsService.TryProjectBlob`, bevel-lej1) — an all-defaults model applied live looks exactly like the skin flipping to Win2000 by itself. `App`'s `settings.Changed` handler runs on the transport thread and **Posts to the UI thread** before touching theme/font resources.
- Domain / VFS / services: `Bevel.Core` — **must not reference Avalonia** (ARCH-02).
- PAL: interfaces in `Bevel.Pal.Abstractions`; `Bevel.Pal.MacOS` (AX + Swift helper), `Bevel.Pal.Windows` (Win32/COM in-proc; Core owns EnumWindows + WinEvent + STA file/icon COM), `Bevel.Pal.Fake` (deterministic; what most tests + `--pal=fake` use). Taskbar on both real PALs is a shell-core *client* for windows/apps/tray; Filer/Desktop keep direct PAL for those and a settings-only client.

## Coupling
- **The `--role=core` process is the SOLE owner of the Swift helper** (core-owns-helper, bevel-6nve): `HelperLifecycle` is added as a hosted service ONLY for Core in `CompositionRoot` (Filer/Desktop keep the singleton lazy, never started); the core serves window/tray/app state to peers over the shell-core IPC, so a peer NEVER launches the helper. `Bevel.Pal.MacOS/HelperProcessHost.cs` launches it; `ResolveHelperBinary` locates the binary (bundle or dev-build). The helper (`pl.ikari.bevel.helper`) is a **separate TCC entity** needing its OWN Accessibility + Screen Recording grants; it **must NOT prompt at boot** (bevel-llfm: AX/Screen Recording prompts block Ping → 5s `WaitForReady` kill mid-dialog → StartupStuck). Boot only preflights (`AXIsProcessTrusted` / `CGPreflightScreenCaptureAccess`); interactive grants go through `MacOSPermissionBroker.RequestAsync` / onboarding. Diagnostics go to **stderr only**.
- Icons render off-thread, cached, shared across processes via a memory-mapped BGRA pool (`MmfBgraPool`) — not re-rendered per process.

## Notes
- **Session protocol (bevel-4zfs) — the core pushes NOTHING on connect.** A UI process wires all its adapters, then sends **Hello** (`ShellCoreClient.StartSessionAsync`); the core replies and pushes the four **(epoch, seq)-stamped** snapshots to that client alone. Deltas are stamped too; seed completion **bumps the epoch** and re-pushes to everyone; a client that sees a seq gap re-issues Hello (rate-limited, 2s). Seq is **PER-CLIENT** (a global seq would make one client's Hello burst eat numbers the others never see); stamping + enqueueing happen under one lock so frame order == seq order. Reconnects auto-re-Hello. `Resync` re-baselines a late subscriber. This deletes the snapshot-eating race class (hence ONE client per process — the keyed `"settings"` client is gone), replaces the seed's BroadcastSnapshot band-aid with the epoch bump, and gives the tray the pull backstop (`GetTrayItems`) it never had. A settings-only peer (Filer/Desktop) never Hello's — it pulls `GetSettings` and listens for `SettingsChanged`, re-pulling on link restore.
- **Live theme colour = two runtime engines, not XAML.** `LunaVariantService` (`src/Bevel.UI/Luna/LunaVariant.cs`; Luna colours Blue/Silver/Black/Purple × gloss) and `ColorSchemeService` (`src/Bevel.UI/ColorSchemeService.cs`; Win2000 schemes) OVERRIDE static tokens and must be `Clear()`'d symmetrically when switching away. Editing the static `.axaml` alone won't change the running look.
- **Never block the Avalonia UI thread** — no `.Result`/`.Wait()`; do heavy work off-thread, marshal the cheap result back.
- App pins `RequestedThemeVariant="Light"`; don't add variant/scope overrides (a Dark leak washes out popups).
- A Popup only opens if its host is attached to a visual tree with a TopLevel — a VM-only `IsOpen=true` can pass a unit test while nothing ever shows (`avalonia-popup-needs-visual-tree`).
- **Task-button Tabs submenu = Apple Events + AX** (bevel-a40b/bevel-osad/bevel-l17f). `ITabProvider` (`Bevel.Pal.Abstractions`) → `Bevel.Pal.MacOS/MacOSTabProvider.cs`, an `/usr/bin/osascript` child per query (RS/US-framed rows; iTerm2 / Chromium-family / Safari dialects; failures collapse to empty by contract). The Gecko family (Zen/Firefox) has NO AppleScript tab dictionary — `GeckoTabEngine.cs` serves it in-proc via accessibility (`AXTabButton` walk + `AXPress`; systemwide AX messaging timeout; press-safety policy in `SelectTarget` refuses ambiguous stale rows), and `GeckoSessionStore.cs` (mozLz4 session store) backfills tab urls by title. Favicons: `TabFaviconStore.cs` reads the browsers' own on-disk caches (Chromium `Favicons` / Gecko `favicons.sqlite`) — sharp edge: the live DBs are UNREACHABLE through both SQLite (Firefox holds locking_mode=EXCLUSIVE) and managed file APIs (.NET's macOS flock contends with SQLite's fcntl locks), so the store raw-syscall-copies then queries. Registered direct in every role like `IFileOpener`. `TaskbarView.PrefetchTabsAsync` fetches + decodes icons off-thread BEFORE `TaskButtonMenu.TryShow` (an open MenuFlyout never repaints) under a 1.5 s budget; the submenu height-caps at 480px and scrolls via the Classic template's own menu scroll viewer. Sharp edge: keep the batched `every tab of window wi` property reads — per-tab reads cost ~24 ms each and measured 8.9 s on a 182-tab sidebar (a pinning test guards this).
- **macOS P/Invoke is declared ONCE per symbol, in the class for its framework** (bevel-uat). `Frameworks.cs` holds every native library path; `CoreFoundationInterop` / `CoreGraphicsInterop` / `ImageIOInterop` / `AccessibilityInterop` / `AppKitInterop` (AppKit + objc + libSystem) hold the declarations. Do NOT start a `private static extern` in a provider file — `tests/Bevel.Pal.MacOS.Tests/InteropConventionTests.cs` fails the build for a symbol declared in two files or a `DllImport` naming a path literal. Was 101 declarations across 11 files with 18 duplicated; now 96 declarations, 0 duplicated. (The first version of the guard required an explicit accessibility modifier and so covered only 80 of 98 — C# defaults to private, and the AppleEvent* files write a bare `static extern`. That blind spot hid two real cross-file duplicates, `SendInt` and `SendNInt`, behind a green test; the regex now matches regardless of how the visibility is spelled.) Type mapping four old silos disagreed on: `CFIndex` → `nint`, `CFTypeID` → `nuint`, CF/AX `Boolean` → `[MarshalAs(UnmanagedType.U1)] bool`. **A bare `bool` return marshals as a 4-byte Win32 BOOL** — that is how `MacOSPermissionBroker.AXIsProcessTrusted` came to read four bytes of a one-byte return and let undefined register content decide an Accessibility check; the same applied to the two `CG*ScreenCaptureAccess` gates. Two sharp edges the guard cannot see: `CGImageSource*` is **ImageIO**, not CoreGraphics, despite the `CG` prefix (filing it by prefix binds the wrong dylib and fails at first call on a real Mac only); and a path passed as a **dlopen argument** is invisible to the guard, so those are centralised by convention (`AppKitInterop.EnsureAppKitLoaded`, `LoginItemRegistrar`). `[LibraryImport]` is deliberately NOT used yet — it rejects non-blittable params without config, and `CFURLCreateFromFileSystemRepresentation` takes a `bool`.
- **Menu-bar consolidation (Strategy C) is owned by the TASKBAR process, never the helper or the core** (bevel-qpir). The native hide — an anchored control `NSStatusItem` (`Bevel.Pal.MacOS/MacMenuBarControl.cs`, ObjC interop, autosaveName `BevelTrayControl`) — needs a serviced AppKit run loop: the helper's hand-rolled `NSApp.run()` deadlocks status-bar IPC (proven live), and the core is headless. So `ShellCoreSystemTrayHost` carries an `applyLocalHide` seam (wired in `CompositionRoot`: `MacMenuBarControl` on macOS, `TrayNotifyWnd` toggle on Windows) plus a `SetTrayHidden` core command that only forwards the state for the helper's poll cadence (900ms while consolidated). `SetConsolidation` RPC on the helper is a state notify, nothing more. Single-item reveal (bevel-6fin): clicking a consolidated icon forwards with `park=true` (`ForwardClickAsync`'s park param threads UI→core→helper); the helper relocates just that item via Ice's self-addressed-event move (`moveItemTargeted`/`itemEvent` in `TrayServiceImpl.swift` — window/pid-addressed CGEvents posted to the session tap, RD-immune) to a slot left of the Clock, presses it, auto-restores after 4s.
- **Task-button unread badge = the DOCK's a11y tree, not the app** (bevel-ijln). `IAppBadgeSource` (`Bevel.Pal.Abstractions/AppBadges.cs`) → `Bevel.Pal.MacOS/MacOSAppBadgeSource.cs`; `Bevel.Pal.Fake/FakeAppBadgeSource.cs` injects labels for tests/`--pal=fake`; Windows registers `NullAppBadgeSource`. **`NSDockTile.badgeLabel` is NOT readable cross-app** — it belongs to the owning process's own `NSApp.dockTile`, and AppKit exposes no foreign tile; don't go looking for one. The only public path is the Dock process (`com.apple.dock`) accessibility tree: per-app `AXApplicationDockItem` → `AXStatusLabel` (the badge), `AXURL` (→ bundle id via `CFBundle`), `AXTitle` (display name). Consequences to keep in mind before "fixing" a missing count: it needs the **Accessibility grant** (no grant → empty, never a throw); an app the Dock doesn't list (`LSUIElement`, Dock-hidden) publishes **nothing**; the label is the Dock's own string, so wide counts arrive **ellipsized** (`"..82"`) — hence `BadgeText` is a string shown verbatim and `BadgeCount`/`AppBadge.Count` is null unless it parses; and it's a **2 s poll** (no public change notification), riding `ShellModel.ReconcileLoopAsync` off-thread with only the finished key→label index Posted to the UI thread. Matching lives in `Bevel.Taskbar/Model/TaskBadges.cs` (bundle id first, app display name as the case-insensitive fallback). **Counts are never inferred from window titles** — a Slack-style `"(7) general"` title must stay badge-free (pinned by `tests/Bevel.Taskbar.Tests/TaskBadgeTests.cs`). The pill is `src/Bevel.Taskbar/TaskBadge.axaml` (`Bevel.Theme.TaskBadge`, a code-drawn rounded `ContentControl`), placed **inline between icon and title** in both task-button templates — not overlaid on the icon, so it survives an icon-size change — and painted from `Bevel.Brush.Highlight`/`HighlightText` (**never a hardcoded macOS red**), which both recolor engines already own. Sharp edge: `Bevel.Brush.HighlightText` was missing from `LunaTokens.axaml` and was added there for this — a token-driven colour must exist in **every** skin or it renders invisible. Distinct from the grouped button's `"(N)"` glomming count (R-TB-6).
- **Task-button pressed state = a projection, never a toggle** (bevel-zk4a). Both strip templates in `TaskbarView.axaml` are `Bevel.Taskbar/TaskButton.cs` — a `ToggleButton` whose `Toggle()` is a no-op and whose style key stays `ToggleButton` (so `Bevel.Theme.ToggleButton` still skins it: Classic `:checked` = RaiseReversed + hatched fill; Luna `:checked` = `Luna.Brush.TaskButtonChecked`, which the variant engine deliberately regenerates as a LIT brighter face, commit 04299e3). `IsChecked` is bound OneWay to `TaskItemViewModel.IsFocused` / `TaskGroupViewModel.IsFocused`, which only `ShellModel.ApplyExclusiveFocus` writes. Sharp edge: **never assign `IsChecked` from code** on these buttons — an Avalonia local-value write disposes the local-priority binding, which is exactly how the old click "snap-back" severed every clicked button from focus for good. Pixel-guarded under both skins by `tests/Bevel.Taskbar.Tests/RenderPressedTaskButtonTest.cs`.
- **Stack flyout = preview grid, and previews are a PAL capability of their own** (bevel-12g/bevel-9elh). `IThumbnailProvider` (`Bevel.Pal.Abstractions`) is CONTENT previews — what is in the file — as opposed to `IIconProvider`'s file-TYPE icons; it returns null whenever the backend can't decode that format, and callers fall back to a larger type icon rather than pretending. `Bevel.Pal.MacOS/MacOSThumbnailProvider.cs` decodes images through ImageIO (`CGImageSourceCreateThumbnailAtIndex`) and PDFs through `CGPDFDocument` — pure C frameworks, all P/Invoke, safe off the main thread; anything else (text, Office, video) has NO preview yet and would need a Quick Look generator. Registered direct in every role like `IFileOpener`, deliberately NOT through the shared icon pool (a thumbnail is per-file content, not a reusable type icon). UI: `src/Bevel.Taskbar/StackFlyoutView.axaml` (its own file — `TaskbarView.axaml` only hosts it in the stack `Flyout`) over `Model/PreviewLoader.cs`, which caches cell bitmaps per path, shares them across cells and `Trim`s them to the folder's live entries. Sharp edge for render tests: the first `CaptureRenderedFrame()` after a batch of bitmaps lands can still be the pre-bitmap composite — capture twice (`RenderStackGridTest.Capture`). Sharp edge for startup (bevel-llfm): `StackViewModel` must arm its `FileSystemWatcher` off the UI thread — default `~/Downloads` can block `FSEventStreamCreate`/`open` on a Files-and-Folders TCC dialog and starve `ReportReady`. Separate path: **taskbar window hover previews** (`TaskbarView.ShowTaskbarTooltip`, bevel-c04q / bevel-gcd) use `WindowPreviewCache` (stale-then-update PNG LRU) + a 150ms show delay; live bytes come from helper `CaptureWindow` (CGWindowListCreateImage via dlsym first, ScreenCaptureKit fallback).
- **Window-chrome geometry is token-driven**, not hand-tuned in the template: the Win2000 border bands (2px bevel · 2px sizing-frame face · 18px caption · 1px separator) come from `theme.json` metrics (`CaptionMargin`, `WindowContentInset`, `CornerRadius`) → `Tokens.axaml` / `LunaTokens.axaml` via `tools/ThemeGen`, and are **pixel-guarded** by `tests/Bevel.Taskbar.Tests/RenderWin2000BorderTest`. Vendored window template: `third_party/classic-avalonia/.../Styles/Window.axaml`; caption buttons: `.../Styles/CaptionButtons.axaml`.
- **Explorer left pane is resizable + persistent.** `LeftSplitter` drag (code-behind pointer-capture in `FileManagerWindow.axaml.cs`, `OnSplitter*`) resizes column 0; the width (`ExplorerLeftPaneWidth`) and the Folders-vs-info toggle (`ExplorerFoldersOpen`) persist via `SettingsService` and restore in `SetSettingsService`. `Components/InfoPane` owns four independently selectable era presets (Win2000/Me Web View, XP Common Tasks, Vista/7 navigation, Win95/NT4 minimal); `FileManagerWindow.UpdateInfoPane` supplies their shared live places, commands, and selection details. Luna's pane aliases preset-local fallback brushes to `Luna.Brush.InfoPane*`; `LunaVariantService.TransformInfoPane` derives each semantic role from the configured source color plus the active base hue and role-specific S/L treatment. Sharp edge: `ApplyFolderOptions` re-lists the directory **only** when a listing-affecting input (hidden files / extension hiding) changed — layout-only settings writes (pane width, toggle, info-pane style) fan out through `App`'s `settings.Changed` but must NOT reset sibling windows' items/scroll/selection. **Don't re-add an unconditional `ReloadWithCurrentOptions()` there.**
- **Type-ahead is a shared service.** `src/Bevel.Core/Input/TypeToFind.cs` (pure, clock-injected, generic) is the one correct type-ahead matcher — prefix accumulation, single-char cycling, forward wrap, `OrdinalIgnoreCase` — fed from real `TextInput` so digits + accents work. `ItemView` uses it (`OnTextInput` → `MoveTo`). The folder tree / Start menu / folder picker / taskbar / desktop grid should **reuse it**, not re-derive a `Key`-decoding copy (that path had a dead digit map, backwards wrap, and no cycling — bevel-p3v3).
- **Accessibility has two non-obvious seams.** (1) The Filer file list exposes screen-reader semantics through `Components/ItemViewAutomation.cs`: each row's visual root is wrapped in a layout-transparent `ItemRow : Decorator` carrying an `ItemRowAutomationPeer` (ListItem + `ISelectionItemProvider` mirroring `ItemViewModel.IsSelected`), and the container is `ItemList : ItemsControl` (List role; `StyleKeyOverride => typeof(ItemsControl)` so it still finds the ControlTheme and realizes rows). Sharp edge: **don't rewrite the `ItemsControl` to a `ListBox`** for a11y — it would break the marquee, rect-based `Hit()`, and the `VirtualizingWrapPanel`; the Decorator+peer is deliberately inert to layout (`Hit()`/`Marquee()` measure the `ContentPresenter`). (2) The taskbar uses **menu-scoped key focus** (bevel-vk4n): it is non-key at idle and `TaskbarWindow.SetKeyFocusAllowed(bool)` flips `canBecomeKeyWindow` true **only** while an owned menu/popover is open (depth-counted `EnterMenuScope`/`ExitMenuScope` in `TaskbarView`), capturing + re-activating the prior app so focus returns. **Never restore the unconditional `SetCanBecomeKeyWindow(false)`-only path or set it `true` at idle** — the bar must not steal focus. From-idle `Ctrl/Option+Esc` rides a native global keyDown monitor that needs the Input Monitoring TCC grant (`taskbar-idle-hotkey-needs-input-monitoring`).
- **Automation window seam is role-aware** (`IShellSurface`, bevel-e7a7). Filer keeps the in-process `FileManagerShellSurface` (addresses live windows by registry id). Every OTHER role — crucially the taskbar host — binds `SpawningShellSurface`: `open`/`reveal` **spawn** a `--role=filer` (via `--open-path=`/`--select=`) instead of building a malformed surface-less window in-process. Registered in `CompositionRoot.AddBevelModules`.
- **Taskbar↔Filer control channel** (bevel-uldj) is how `select`/`query windows`/`query selection` reach live windows in split mode. Each Filer hosts an `FilerControlServer` on a per-pid rendezvous socket (`Bevel.App/ShellCore/FilerControlEndpoint.cs`, `filer-<pid>.sock` in a 0700 env-published dir); the taskbar dials them via `TaskbarFilerControlClient` to aggregate queries (frontmost-first) and route `select`. Composite `WindowRef = (regId<<16)|localId` (regId starts at 1 so a composite is never 0); `Decode` routes a ref back to its owning pid. `SpawningShellSurface`'s channel client is optional — Desktop/Core bind the surface but leave it null and fall back to the clear "no window" result. The channel also carries the **park handoff** (bevel-t48y): `FilerCommandKind.Show` tells a parked Filer to navigate + show its hidden window; the window-side work is `IParkedFilerWindowHost` (`ParkedFilerWindowHost` — the parked window is built hidden and UNREGISTERED, and the handoff registers it, so a hidden park never appears in the window aggregation).
- **Start-menu Show/Hide Desktop toggle** (bevel-gdie): the desktop surface is OFF by default. Start-menu verbs go child→launcher over `LauncherControl` (`SpawnDesktop`/`CloseDesktop`/`QueryDesktop`), driving the supervisor's runtime add/remove. Set `BEVEL_ENABLE_DESKTOP=1` to spawn it at boot instead.
- **Process health is heartbeat-driven, not just `HasExited`.** Children write `starting`/`ready`/`failed` + `BuildStamp` under `BevelRuntimeDir.HealthDir`; the launcher's `ShellHealthMonitor` Holds a XAML/startup failure (native alert + `status` file) instead of crash-looping, Restarts a stamp/protocol mismatch onto the current binary, and Restarts the core when a ready UI has no link. Not-this: `LostCoreAutoRepair` is the *taskbar-side* complement (click-equivalent RestartCore after a grace period) — it does not replace the launcher monitor.
- **Build/launch hygiene.** Packaged publish is `PublishReadyToRun` (crossgen per role, bevel-k93j). A normal `dotnet build` emits **no `Bevel.App` apphost** — `UseAppHost` is gated on `BevelPackaging` in `Directory.Build.targets` (a stray apphost pollutes Spotlight/LaunchServices; the packaged bundle also drops a `.metadata_never_index` marker). So `dotnet run` executes the DLL via the shared `dotnet` host; only `/Applications/Bevel.app` (via `install-local.sh`) is a real app.
